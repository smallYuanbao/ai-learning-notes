# LangChain核心概念

> 📅 学习日期：2026-08-02
> 🔗 关联面试题：框架专题「LangChain 解决了什么问题？」

## 1. 定义

**LangChain** 是一个LLM应用开发框架，把AI开发中常见的操作（如调大模型、检索文档、管理对话历史、编排流程）封装成了标准化的组件。

### 1.1 为什么需要LangChain？

原始的LLM（如GPT4）虽然强大，但像一个”孤岛“：

1. 它无法访问实时数据或私有数据（如公司内部文档、数据库）。
2. 他无法与外部世界交互（如发送邮件、查询天气）。
3. 它没有”记忆“，会忘记之前的对话内容。

LangChain 则像一个”桥梁“，将LLM与外部世界连接起来，让开发者能构建真正有用的、有上下文感知能力的应用。

## 2. 核心组件

LangChain 提供了一系列模块组件，方便组合使用：

- **模型（Models）**：标准化与各种LLM（如GPT、Claude、DeepSeek）和嵌入模型的交互。

- **提示词（Promopts）**：提供管理和优化提示词（Prompt）的工具。

- **链（Chain）**：将多个步骤（如调模型、使用工具）按照顺序连接起来，上一个步骤的输出是下一个步骤的输入。这是构建复杂工作流的核心方式。

- **检索器（Retrievers）**：从外部数据源（如向量数据库）查找相关信息，是实现RAG的关键。

- **工具（Tools）**：允许LLM调用外部API、数据库或执行特定函数，扩展其能力。

- **智能体（Agents）**：使用LLM作为推理引擎，自主决策调用哪个工具以及调用顺序。ReAct

- **记忆（Memorys）**：在不同轮次的对话中保存和传递上下文信息，让应用拥有”记忆“。

- **向量存储（Vector Stores）**：用于存储和搜索文本的向量表示，是RAG应用的基础。

**关键理解**：LangChain 不是新概念，只是把已经手写实现过的东西做成了标准组件。学它不是为了”学会新东西“，而是为了理解”业界是怎么封装这些能力的“。


### 2.1 四大核心概念：

| 组件 | 作用 | 我项目里的对应实现 |
|------|------|------|
| **Chain** | 把多个步骤串联成固定流程 | `unified_agent_chat` 的 7 步流水线 |
| **Agent** | LLM 自主决策调哪个工具、走哪条分支 | ReAct 循环 + Function Calling |
| **Memory** | 管理对话历史，支持多轮上下文 | `session_manager`（短期）+ `user_profile`（长期） |
| **Tools** | 标准化外部工具的接口定义 | `WEATHER_TOOL` Schema + MCP 工具列表 |

## 3. LangChain vs LlamaIndex

- LangChain：是一个通用型的LLM应用程序开发框架。它侧重于工作流编排，擅长将模型调用、工具使用、决策逻辑等串联成一个完整的应用

- LlamaIndex：是一个数据框架，它侧重于数据检索。专注于如何高效地将外部数据接入LLM，在RAG场景下有更丰富的检索策略。

***适用场景：***

- LangChain：复杂的工作流、多智能体协作。

- LlamaIndex：高性能的文档检索和问答。



## 4. 原生 vs 框架的差异

| 对比维度 | 裸写（你的项目） | LangChain |
|------|------|------|
| LLM 调用 | 直接调 DeepSeek API | `ChatOpenAI` 封装，换模型只改变量 |
| Prompt 管理 | 自己拼字符串 | `ChatPromptTemplate`，变量占位、模板复用 |
| 流程编排 | 手动写函数调用顺序 | `\|` 管道符串联（LCEL），直观但灵活度受限 |
| 学习成本 | 需要理解 API 细节 | 需要理解框架抽象层 |
| 灵活性 | 极高，完全控制 | 受限于框架组件，自定义需额外开发 |
| 适用场景 | 需要精细控制每个环节 | 快速原型、标准化任务 |

**LCEL：LangChain Expression Language，一种声明式语法，用于更轻松地构建和组合链**

**核心结论**

> “LangChain 的本质是把 LLM 开发中的常见模式抽象成了可复用的组件。它适合快速原型和标准化任务。我的项目选择了裸写，因为我需要精细控制混合检索的融合策略、三级降级逻辑和自定义评估体系——这些在 LangChain 的标准化组件里很难实现。但 LangChain 的设计思想（Chain/Agent/Memory/Tools）我在自己的代码里都实现过，所以如果需要，我可以很快上手。”


## 4. 我的选型理由
- 选择裸写：需要精细控制混合检索、三级降级、自定义评估体系
- LangChain 思想已掌握：四个核心概念在项目中都有对应实现
- 如果团队有标准化需求，可以快速上手 LangChain
