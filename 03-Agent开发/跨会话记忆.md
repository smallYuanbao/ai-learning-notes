# 跨会话记忆

> 📅 实现日期：2026-08-02
> 🔗 关联面试题：Agent 专题 题12（LLM Agent 长期记忆能力的实现方法）、题22（短期记忆与长期记忆的差异）

## 1. 核心思路

跨会话记忆解决的是“用户换了新会话后，Agent 还能记住之前聊过的关键信息”。

**实现流程**：

对话结束 → LLM 提取关键信息（月龄/过敏史/关注主题）
→ 存入 ChromaDB (user_profiles collection)
→ 下次新会话时检索档案 → 自动注入 System Prompt


## 2. 与短期记忆的区别

| 类型 | 存储位置 | 生命周期 | 我的实现 |
|------|---------|---------|---------|
| **短期记忆** | 服务端内存 dict | 当前会话，重启丢失 | `session_manager.py` |
| **长期记忆** | ChromaDB（user_profiles） | 跨会话持久化 | `user_profile.py` |

## 3. 实现细节

### 3.1 信息提取
- 在审核完成后，调 LLM 从对话中提取结构化信息
- 输出 JSON 格式：{baby_age, allergies, concerns, other}
- temperature=0 保证提取结果稳定

### 3.2 存储策略
- 以 session_id 为文档 ID，支持 upsert
- 新信息自动合并到已有档案中

### 3.3 注入方式
- 新会话开始时，检索用户档案
- 转为自然语言文本，拼入 System Prompt

## 4. 代码位置
- 用户档案管理：`app/services/user_profile.py`
- Agent 主流程集成：`app/services/agent.py` → `unified_agent`

## 5. 面试怎么讲

> “我实现了跨会话的长期记忆机制。对话结束后，系统用 LLM 自动提取用户关键信息——比如宝宝月龄、过敏史——存入 ChromaDB 的用户档案库。下次新会话时，系统自动检索档案并注入 System Prompt，让 Agent 能跨多次对话记住用户情况，提供个性化建议。档案存储支持 upsert，新信息会自动合并到已有档案中。”

## 6. 后续优化方向
- 记忆衰减：太久未更新的档案自动降低权重
- 隐私保护：敏感信息脱敏后再存储
- 记忆容量管理：定期清理长期未使用的档案
