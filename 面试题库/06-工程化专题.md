## 题3：用户停止生成时，LLM 推理终止、资源释放的实现及资源泄露防范

**我的回答**

用户在流式输出过程中点击"停止生成"，前端断开 SSE 连接，但后端还在继续调 LLM 生成 token——算力浪费、成本空烧。解法分两步：

**1. 感知客户端断开**：在流式生成器里每输出一个 chunk 前检查 `request.is_disconnected()`，客户端断开立即 `break` 终止循环。

**2. 释放资源**：退出循环后调用 `stream.close()` 关闭 LLM 连接，确保 GPU/Token 不被继续消耗。

```python
async def generate_stream_with_interrupt(user_message, request):
    for chunk in stream:
        if await request.is_disconnected():
            break  # 客户端断开，终止生成
        yield delta
    stream.close()  # 释放 LLM 连接资源
```

**项目关联**：baby-ai 的 `/api/chat/stream` 接口已实现中断检测 + 资源释放，截图证明客户端断开后后端立即停止生成。

**关键词**：流式中断、is_disconnected、资源释放、stream.close()

## 题5：多轮对话 + 流式输出的消息有序性、上下文完整性保障及跨服务流式透传实现

> ⚠️ 跨服务流式透传部分待实践后补充

**我的回答**

**消息有序性保障**：多轮对话中每条流式 chunk 通过 `session_id` 关联到同一会话。前端维护消息队列，按收到顺序拼接，不做乱序重排——SSE 协议基于 TCP，天然保证单连接内的消息顺序。

**上下文完整性保障**：通过 `session_manager` 管理对话历史。每轮对话结束后将 user message 和 assistant 完整回复写入历史，下一轮请求时从历史中读取完整上下文注入 Prompt。流式输出中途断连不会丢失上下文——已生成部分从历史中读取。

**项目关联**：baby-ai 的 `/api/chat/stream` 已实现上述机制，`session_manager` 负责对话历史维护，前端按 SSE 顺序拼接展示。

**关键词**：多轮对话、SSE、session_id、消息有序性、上下文完整性

## 题10：流式推理中 LLM 模型报错的兜底策略设计

**我的回答**

LLM 流式调用可能遇到 API Key 过期、超时、返回格式错误，没有兜底时用户看到空白或报错堆栈。我的策略是 try/except 包裹整个流式生成器：

```python
async def generate_stream_with_fallback(user_message):
    generated_content = ""
    try:
        for chunk in stream:
            delta = chunk.choices[0].delta.content
            if delta:
                generated_content += delta
                yield delta
    except Exception as e:
        if generated_content:
            yield f"\n\n[生成中断：{str(e)[:100]}，以上为已生成部分]"
        else:
            yield "抱歉，服务暂时不可用，请稍后重试。"
```

两层兜底：如果已经生成了一部分——返回已生成内容 + 友好提示，用户至少能看到部分结果；如果完全没生成——返回固定话术，不让用户看到空白页或错误堆栈。

**项目关联**：baby-ai 的 `/api/chat/stream` 已实现错误兜底，截图证明 API 异常时返回友好提示而非报错。

**关键词**：流式兜底、try/except、异常处理、友好提示
